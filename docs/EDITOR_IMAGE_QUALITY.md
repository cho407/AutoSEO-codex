# JSON 편집 실행과 블로그 이미지 품질

## 구현 범위

콘셉트·본문·사실 판단은 Codex, 입력·서식·저장은 로컬 Playwright가 맡는다.
문서 JSON → 검증 → 고정 카탈로그/의사결정표 → 후조건 확인 → 체크포인트 순서다.
JSON 자체가 토큰 절감을 보장하지 않는다. 반복 판단과 큰 도구 출력을 줄이는 것이
목표이며, 기존 드라이버도 정상 클릭마다 모델 API를 호출하지 않았다.

- 두 편집기의 `plan <document>`: 본문 없는 기능/개수 요약, 브라우저 실행 없음.
- `capabilities`: 모든 기존 기능의 automatic/guided/unavailable 분류와 결정표.
- `data/editor-decision-tree.json`: 허용된 boolean 사실만 받는다. 임의 선택자,
  JavaScript나 발행 승인을 실행 규칙으로 넘길 수 없다.
- 완료 동작은 검증 후 생략, 중단 동작은 표면/후조건에 따라 기록 또는 진행.
  불명확한 업로드·저장·발행은 자동 재시도하지 않는다.
- 기본 결과는 완료 수·저장 상태·진단 수·편집 시간만 담는다. URL/전체 체크포인트는
  로컬에 남는다. 필요한 초안 링크만 별도로 읽어 전달하고, 원문/스크린샷/쿠키를
  매 동작마다 모델에 돌려주지 않는다.
- 네이버는 선택 변경 후 서식 상태를 일괄 조회하고 필요한 토글만 변경한다.
  모호한 툴바는 기존 접근성 탐색으로 돌아간다. 본문 해시/저장 검사는 유지한다.
- 티스토리는 일괄 입력을 유지하고 모드명과 실제 편집 가능한 본문을 확인한다.
  고정 150ms 대기를 제거했으며 브라우저 재시작이나 별도 서비스는 추가하지 않았다.

## 이미지 하한

`data/blog-image-policy.json`과 `blog_image.py`는 작성 모델과 독립적인 기본값을
적용한다. 자동 게이트 대상은 hero/explainer/OG이며 실제 사진 생성은 기존 호스트
이미지 도구가 맡는다. 로컬 도구가 새로운 사진 생성 모델인 것은 아니다.

| 항목 | 기준 |
|---|---|
| 기본 스타일 | 인스타 카드뉴스형: 한 장에 한 메시지, 짧은 제목과 관련 사진·삽화의 조합. 큰 글자/의도적인 패널은 허용하고 빽빽한 보고서식 격자는 피함 |
| 대표/설명 이미지 | 카드뉴스 기본 1:1 1600×1600/최소 1200×1200, 4:5 1280×1600/최소 1080×1350 지원. 16:9 1600×900/최소 1280×720, 4:3 1600×1200/최소 1200×900도 선택 가능. 비율 오차 3% 이내 |
| OG | 1200×630 |
| 파일 | PNG/JPEG/WebP, 정지 이미지, 최대 8 MiB/24 MP, 정상 디코딩 |
| 실제 검수 | 주제 적합성·구도(의도하지 않은 PPT형 구성 거절)·모바일 가독성·생성 오류·사실성·잘림 |
| 재시도 | 생성 1회 + 수정 생성 최대 1회, 추가 구매 없이 가능한 경우만 |
| 대체 | 사용 권한이 확인된 실제 이미지, 사용자 확인 또는 선택 이미지 생략. 카드/단계 템플릿은 명시적으로 선택한 경우에만 사용 |

`BlogImageBrief v1`의 기본 `layout`은 `social-card`, 기본 색은 `contextual`이다.
구체적인 `visual_subject`를 필수로 받고, `art_direction`과 `article_context`로
질감·광원·구도·금지 요소와 본문에서의 역할을 짧게 전달한다. 본문 전체를 반복 전달하지
않는다. `editorial`/`photo`의 제목은 메타데이터이며 이미지에 자동으로 쓰지 않는다.
의도적으로 선택한 `cover`는 종이 질감·손글씨 등의 짧은 표지를 허용한다. 제목과
그림의 필요를 구분하며, 모든 이미지에 텍스트를 금지하거나 베이지 톤을 강제하지 않는다.

참고 글은 표지·자료 사진·도식과 배치 위치를 구분해 읽고 유지/회피/불확실한 요소만
정리한다. 기존 생성물이 있다는 이유로 선호한다고 단정하지 않는다. 사용자 블로그 주소,
원문과 이미지는 공개 플러그인에 복사하지 않는다. 제품·현장·서비스의 증거가 필요하면
실제 사용 허가된 자료를 우선하고 AI 이미지로 공식 화면이나 취재 사진을 꾸미지 않는다.
도식은 설명에 도움이 될 때 관련 문단 근처에 배치하며 표지와 요약 카드를 본문 앞에
연속 배치하지 않는다.

기술 검사만으로는 visual-review-required다. 실제 파일을 본 사용자/에이전트가
모든 시각 검사를 통과시켰고 이미지/브리프 해시가 같아야 accepted가 된다. 이는
확인 기록이지 자동 미적 점수나 검수자의 오류가 없다는 증명은 아니다.
저해상도 확대, 작은 글자로 축소하기, 사진/삽화를 임의 카드로 대체하기는 금지한다.
`plan`은 여섯 검수 항목의 구체적인 기준도 반환한다. PPT형 여부는 실제 시각 검수자의
판단이며 자동 분류기가 아니다. `render`는 명시적인 `card`/`steps`만 받고 기본 예제의
편집 삽화는 거절한다. 로컬 한글 글꼴이 없거나 글이 넘치면 중단한다.

생성 파일·brief·review를 `generated_images`에 선언하면 두 편집기가 업로드 전 검사하며
메타데이터도 문서 해시에 포함된다. 기존 문서/사용자 사진을 위해 필드는 선택적이다.
픽셀만으로 생성 여부나 선언 누락을 판별하지 못하므로 작성 스킬은 모든 생성 자산의
선언을 요구한다. 모자이크 후 파생 이미지도 직접 확인한다. 수직 인포그래픽/커스텀
비율(지원하는 16:9/4:3/1:1/4:5 외)의 자동 게이트는 확장 대상이며 현재는 검수된 로컬
산출물과 자동 연결을 구분한다.

참고 스타일은 실제 열어본 관련 글에서 선택하며 범용 디자인 사이트를 매번 검색하지 않는다.
참고 링크가 이미지 재사용 허가를 뜻하지는 않는다. 크기/가독성 정책은 네이버 상위 노출 요건이 아니다.
[Google 이미지](https://developers.google.com/search/docs/appearance/google-images)와
[Discover 안내](https://developers.google.com/search/docs/appearance/google-discover)는 관련성·품질·
표시 조건을 참고하는 자료이지 순위 보장이 아니다.

## 검증과 남은 작업

`tests/benchmark_editors.py`: 로컬 모의 편집기, 플랫폼별 20문단·2이미지·5태그와
제목 변경 경로. 워밍업 2회/측정 10회. 로그인/실제 네트워크/이미지 생성/리서치를
제외한다. 구버전 비교는 동일 테스트에서 Cmd+End 커서 이동을 정규화한다. 구버전이
macOS에서 긴 글 입력을 완료하지 못하는 문제와 순수 성능 개선을 분리하기 위해서다.
토큰은 모델/tokenizer마다 달라 출력 바이트나 호출 횟수와 동일시하지 않는다.

2026-09-21, 동일 macOS/Chromium 151 환경에서 c182dab와 변경본을 순서대로 실행한
로컬 중앙값(워밍업 2회, 10회 측정)은 다음과 같다. 실서비스 속도 보장은 아니다.

| 경로 | c182dab | 변경본 | 시간 감소 |
|---|---:|---:|---:|
| 네이버 20문단·2이미지·5태그 | 6,589.49 ms | 2,825.45 ms | 57.1% |
| 티스토리 같은 분량 | 884.05 ms | 458.75 ms | 48.1% |
| 네이버 제목 입력/확인 | 43.81 ms | 27.95 ms | 회귀 없음 |
| 티스토리 제목 입력/확인 | 22.99 ms | 16.29 ms | 회귀 없음 |

제목 경로는 변경하지 않았으므로 그 차이는 실행 환경의 변동도 포함한다. 측정은
모의 편집기에서의 로컬 동작을 비교하며 실제 이미지 업로드·로그인·AI 생성 시간과
전체 글 작성의 토큰 사용량은 측정하지 않았다. 실제 토큰 감소율은 미측정이다.

실제 사용자 초안의 글자·서식·이미지·저장 상태, 모드 표시 차이, 고급 안내형 컴포넌트는
실검증 대상이다. 실제 발행·예약은 글별 승인 후 별도로 확인한다. 이 구현 작업은
실계정 로그인/업로드/게시, 유료 API 사용이나 새 브라우저 설치를 수행하지 않는다.
